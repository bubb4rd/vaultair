Where it lives

  • A 32 px icon button in the page header, left of the window controls. Same slot on every page.
  • Unread updates: a 7 px brand dot on the button (same signal as the sidebar's active icon, so no new colour).
  • Click opens a 408 px popover on the popover surface, 12 px overlay radius, hairline strong border. No shadow, no glass.
  • Ctrl+K: "what's new" opens it too.

Anatomy

  • Entries grouped by version (mono), newest first. Installed version gets an "Installed" pill in brand.
  • Three densities, chosen per change: media entry (116×68 looping clip with play badge + mono duration, or a still with an image glyph; clips play on hover, open larger on click), text entry (same chip / title / sentence, text runs full width; no empty thumbnail slot), and one-liners under "Also in this version" (chip + one line, ellipsised).
  • Rule of thumb per release: at most 2 or 3 media entries, text entries for anything that needs a sentence, everything else as one-liners. A patch release is usually just one-liners.
  • Type chip follows the status system: icon + text + colour. New = secure green, Improved = brand blue, Fixed = dormant grey. Never colour alone.
  • One action link per entry at most, in the brand blue, deep-linking into the app.
  • Older versions collapse to one row each. Footer: release notes (external) and the badge preference.

Behaviour

  • Reading an entry (opening the popover) clears its dot after it has been on screen; "Mark all read" clears everything.
  • "Tips" tab reuses the same entry shape for short how-to clips that aren't tied to a release.
  • Content ships inside the app build (updates.json + .webp/.webm assets), so the CSP stays strict and nothing is fetched.
  • Reduced motion: thumbnails never autoplay; play is a click.
